# Pulu Chatbot - Project Architecture & Documentation

This document provides a comprehensive breakdown of the "Jalian Kanaran" (Pulu) Chatbot project. It covers the complete architecture, how the frontend and backend communicate, and the internal mechanics of the AI routing system.

---

## 1. High-Level Architecture
The project is built on a lightweight **Node.js + Express** backend, paired with a **Vanilla JavaScript + HTML/Tailwind** frontend. It leverages the **Gemini API** for AI generation but communicates with it using the standard OpenAI chat completions format (supported by Gemini's beta endpoints).

The core philosophy of this app is to be a fast, stateless (mostly), and highly aggressive sarcastic bot for a hackathon/tech-fest environment.

---

## 2. Backend Engine (`server.js`)
The backend is an Express server responsible for serving the frontend files, managing chat history, and securely communicating with the Gemini API.

### Core Features:
- **Environment Variables (`dotenv`)**: Securely loads your API keys (`AI_API_KEY`, etc.) from the `.env` file so they are never exposed to the client.
- **Cache Defeating**: A custom middleware forcefully injects `Cache-Control: no-store` into all static files (`HTML/CSS/JS`) to ensure the user's browser always loads the latest code.
- **In-Memory Rate Limiter**: A simple `Map()` object tracks the IP addresses of incoming requests to prevent spam. It limits users to **15 requests per minute** to protect your API quota.

### API Routes:
#### Chat History API (`/api/sessions`)
A simple file-based JSON database (`chats.json`) is used to store chat history permanently on the server.
- `GET /api/sessions`: Reads `chats.json` and returns all past user sessions to populate the sidebar.
- `POST /api/sessions`: Saves a new message pair (User Query + Bot Reply) to the JSON file.
- `DELETE /api/sessions/:id`: Deletes a specific chat session from the file.

#### The AI Engine (`/api/troll`)
This is the heart of the application. When a user sends a message, it goes through a multi-stage pipeline:

1. **The Distress Circuit Breaker**: Before sending data to the AI, a regex function (`containsDistressSignal`) from `persona.js` scans the user's message for words related to self-harm or severe distress. If triggered, the bot immediately drops the persona and returns a pre-written supportive message (`SAFE_FALLBACK_REPLY`).
2. **Phase 1: The Analyzer AI**: The backend makes an API call using the `ANALYZER_PROMPT`. This AI's job is **not** to reply to the user, but to analyze the user's input and decide how Pulu should react. It returns a JSON object specifying the desired length (e.g., "SHORT", "LONG") and the roasting strategy.
3. **Phase 2: The Generator AI**: The backend takes the instructions from the Analyzer, combines them with the main `SYSTEM_PROMPT`, and makes a second API call to generate the actual response in Manglish.
4. **Final Safety Check**: The generated response is scanned one last time by the distress circuit breaker to ensure the AI didn't hallucinate anything inappropriate. Finally, it is sent back to the frontend.

## 3. Frontend Architecture (`public/index.html`)
The frontend is built without heavy frameworks like React. It uses Vanilla HTML, JavaScript, and Tailwind CSS (via CDN) for rapid development and styling.

### UI States:
- **`home-view`**: The initial state featuring the large animated "Jalian Kanaran" mascot, the tagline, and suggested prompt chips.
- **`chat-view`**: The active conversation state, containing the scrolling list of messages.

### Key JavaScript Functions:
- **`handleSend()`**: 
  - Grabs the text from the input bar.
  - Hides `home-view` and shows `chat-view`.
  - Injects a "Pulu is typing..." indicator.
  - Makes an asynchronous `fetch()` POST request to `/api/troll`.
  - Receives the response, removes the typing indicator, and calls `addMessage()`.
- **`addMessage(text, sender, safeMode)`**: 
  - Dynamically creates HTML `<div>` elements for messages.
  - Contains a lightweight custom Markdown parser to convert `**bold**`, `*italic*`, and `### Headings` generated by the AI into actual HTML tags.
  - Distinguishes between User messages (right-aligned, standard styling) and Pulu messages (left-aligned, aggressive yellow styling).
- **History Management (`fetchSessions`, `saveSession`, `loadSession`)**: 
  - Communicates with the backend `/api/sessions` to keep the sidebar updated. Clicking a history item clears the current view and repopulates it with the saved messages.

---

## 4. Persona & Configuration (`persona.js`)
This file dictates exactly *who* the bot is and how it behaves.
- **`SYSTEM_PROMPT`**: The massive master prompt that dictates Pulu's Manglish dialect, his specific vocabulary ("mone", "thallu", "pinnallah"), and his zero-empathy roasting guidelines.
- **`ANALYZER_PROMPT`**: Instructs the initial AI model on how to categorize incoming text and structure JSON output.

---

## 5. Deployment configuration (`vercel.json`)
Because the app relies on the `server.js` Node engine rather than just static HTML files, the `vercel.json` file is required. It instructs Vercel's `@vercel/node` builder to route all incoming web traffic straight to `server.js`, allowing the Express server to handle the API routes and static file serving perfectly in a serverless environment.
